# 近 12 个月门店经营数据整理与复盘

## 背景

区域四家门店（北京朝阳店、北京海淀店、上海静安店、深圳南山店）近 12 个月的流水，上周从收银系统里按月导出来了，放在 `raw/` 下，一个月一个文件，文件名就是月份（2025-10 ~ 2026-09）。

导出的老毛病还在，拿到手的数据是脏的。统计之前必须先洗干净，不然出数一定是错的。

## 数据说明

列：`order_id, date, store, category, customer, qty, unit_price, amount`

已知的脏数据有几类：

1. 日期格式不统一 —— 导出的同事手写习惯不同，同一天会写成 `2025-10-05`、`2025/10/5`、`2025.10.05` 三种
2. `category` 的大小写和空格不统一 —— 有 `Milk Tea`、`MILK TEA`、`milk tea`、` Milk Tea` 各种写法
3. `store`、`customer` 有的带首尾空格
4. `order_id` 相同的行会出现整行重复（导出重跑了）
5. `amount` 有时是空的（导出超时丢了字段）
6. `qty` 有时是空的（同样是导出超时），这种是废行

## 清洗规则（按这个来，不要自己发明）

- 日期统一成 `YYYY-MM-DD`
- `category` 去掉首尾空格后统一成首字母大写：`Milk Tea` / `Coffee` / `Bakery`
- `store`、`customer` 去掉首尾空格
- `order_id` 相同的重复行只保留一条
- 数量为空的整行剔除
- `amount` 为空时，用 `qty × unit_price` 补算
- 退货单（`qty` 为负）不计入销售额，但要单独统计笔数
- 金额一律保留两位小数

## 交付物

1. **`out/clean/`** —— 洗干净的 12 个月数据，一个月一个文件，列名不变，文件名沿用原名
2. **`out/summary.json`** —— 全年汇总，格式：

```json
{
  "total_sales": 全年销售额,
  "order_count": 有效订单数（不含退货）,
  "return_count": 退货笔数,
  "dropped_rows": 剔除的废行数,
  "duplicate_rows_removed": 去掉的重复行数,
  "by_store":    {"门店": 销售额},
  "by_month":    {"YYYY-MM": 销售额},
  "by_category": {"分类": 销售额},
  "top_customers": [{"name": "客户名", "amount": 累计消费额}]
}
```

`top_customers` 给累计消费额的前三名。

3. **`out/report.md`** —— 给管理层看的经营复盘：四家店横向对比、12 个月的走势、品类结构、值得注意的问题和建议。报告里的数字必须和 `summary.json` 对得上。

## 怎么做

这次数据量比平时大，一个人做慢，你带几个人一起做：

- 有人负责洗数据和出数
- **要有一个人独立复核**：不看前一个人的清洗脚本，自己从 `raw/` 里的原始文件重新算一遍，两边数字必须能对上；对不上就得查清楚，是规则理解不一致，还是真算错了 —— 查明白再定稿
- 有人负责写报告

你负责最后的验收和交付。
